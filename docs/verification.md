# Verification

How the system was tested against each line of the brief, and what has not been
tested yet. Every ✅ in the first table is checked automatically by
[`scripts/e2e.sh`](../scripts/e2e.sh) (`make e2e`).

Last full run: a fresh install from nothing on local k3d, two users,
**82 checks passed, 0 failed, 1 skipped** (the chat agent with a real model needs an
LLM key).

## Definition of done (brief, page 3), each item and its proof

`scripts/e2e.sh` checks every line below except the ones marked manual.

| Brief item | Result | Proof |
| --- | --- | --- |
| Storefront: add to cart, check out with COD | ✅ | e2e checks out as a guest through the storefront's own Store API with Cash on Delivery |
| Order visible in WooCommerce admin | ✅ | e2e reads it back through WooCommerce (`woo__get_order`); admin page itself: manual |
| Chat, user A: create a product, it appears on the storefront | ⚠️ needs key | Tool path proven (A creates the product through the gateway, storefront shows it). Chat run itself skipped: no LLM key. The loop was tested with a scripted model. |
| Chat, user A: "what orders came in today" returns the hand-placed order | ⚠️ needs key | Same: `woo__list_orders {date: today}` returns the order; chat run skipped |
| User B with only gateway URL + own key: sees every enabled server's tools | ✅ | e2e as B over raw MCP: tools of `woo`, `everything`, `toolbox`. Also tested with the official MCP SDK client. Claude Code/Cursor on camera: manual |
| User B: same orders question | ✅ | e2e |
| One prompt using two upstreams | ✅ tools / ⚠️ prompt | Tools of two servers called in one session; an actual model prompt needs Claude Code on camera |
| Revoke B's key, next call rejected | ✅ | e2e: 401, and the attempt is in the audit log as `rejected` |
| Disable a server, its tools disappear (chat and external) | ✅ | e2e: gone from `tools/list`, calls refused; the chat agent lists tools fresh each turn |
| Kill an upstream pod: others keep working, dashboard shows Unreachable | ✅ | e2e deletes the `everything` pod: toolbox answers, status turns Unreachable, then reconnects. Dashboard refreshes every 5 s |
| Every call in the audit log, right user | ✅ | e2e checks user, server, tool, time, duration, outcome, and that A's and B's calls are not mixed |
